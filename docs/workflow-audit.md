# Workflow audit and implementation

This audit uses retained Gepard and earlier convoy evidence to improve the existing harness entrypoint. It does not change vehicle gameplay or qualify a release. Publication remains manual and unconfirmed. Starting public revisions were harness `58d8e8bb7d9a3dc4b651a3fda6eb19024a5b3ca3` and Gepard `05f1070ef9d3f2436dbb98d95182f29d94c8dc68`, verified against remote main on 20 October 2026.

The [sanitized validation receipt](audits/workflow-validation-2026-10.json) links these findings to source fingerprints, timed comparisons, native assertion measurements and original-evidence hashes. Exact local paths and original artifacts remain in the private audit handoff.

## Coverage and limits

The local coverage inventory contains **37,462 metadata entries** after explicit exclusions of Git/dependencies, profiles/downloads, selected source/asset snapshots, reference/raw directories and recordings. A bounded content scan read **794 selected documents, scripts and logs**: 193 from the Gepard task, 217 from native projects, 102 convoy main documents, 120 newer convoy documents, 132 convoy native logs, 14 public-harness notes and 16 capture-lab notes. Keyword matches index failures/limits; they are not manual inspection or causal proof for every file.

Detailed inspection covered the damage/acceptance runners and results, packaged-validator repair, screenshot director/launchers/failed compiles, human truck/access handoff, night/exposure evidence, audio provenance/integration plan, repository/release handoffs, experimental concurrency review, and convoy validation/lifecycle/takeover records. Twenty-two recent turns from the development task were read through the supported task API, including failures and interrupted work. Those private conversations are not published here. Older convoy work was examined through retained source notes, summaries and logs rather than a complete historical transcript.

The supported local memory-summary folder was empty. Relevant repository/workspace AGENTS instructions were read; the inspected task and harness locations provided no additional `.agents/skills` entrypoint. Raw transcript/session directories were not accessed. Not all old tasks, recordings, crashes, private downloads or every native log have been individually inspected. Local private coverage/content manifests retain exact source mappings, sizes, hashes and scan methods; public notes omit machine-specific private information and raw chats.

## Representative validation

The reproducible local benchmark uses actual sealed private Gepard fixtures and authored native rifle projectiles/HEIT fragments. Each case uses a fresh process/subject with the original source manifest, received damage callbacks, screenshots, run identity and normal closure evidence. It makes no real-world armor or probability claim.

The existing addon Acceptance script already supported grouped batches. This change generalizes selected cases, preflight and result contracts across workflows; it does not claim to invent native batching. Initial integration still required one private bridge/job. The first new batch attempt selected an incompatible interpreter and launched no Game; its error and fresh corrected retry are retained. A fresh private native-run directory assumption also failed before launch and was corrected. These are setup costs, not hidden successes.

The private functional successor changes one test director, with **1,460 of 1,461 source files unchanged** and no gameplay asset tuning. Its first experimental native pair recorded insufficient traverse and reentry timeouts; those failures remain preserved. Two healthy controls exposed inactive native ADS/context. Restoring the ordinary player-camera path for functional stages and applying inputs before the control phase established actual ADS/context readiness, roughly 103°/53° movement and five rounds per gun in a healthy control. This is a tested setup correction, not an isolated proof about every camera API.

Both final incoming-damage cases then passed measured traverse, actual firing and public exit with qualified infrastructure and normal owned closure. **Both complete loops remain FAIL:** public reentry also times out in the healthy control, and firing after reentry is NOT_TESTED. Incoming damage is therefore not established as the cause of that access failure; its fixture/old-addon action boundary remains unresolved. No gameplay fix or current frozen-release regression is claimed. Ordinary keyboard/human acceptance and post-hit powered driving remain separate and untested. More camera/input variants have diminishing value until that specific public-entry boundary is investigated in an addon task.

Automated coordinator tests cover missing classes/worlds/dependencies, duplicate GUIDs, pinned-file drift, duplicate/nonfinite JSON, missing/stale/malformed results, missing assertions, measured FAIL continuation, infrastructure/lifecycle stop, cancellation, deadline, low storage, excessive adapter output, unresponsive adapter preservation and fresh reruns. Node tests cover discovery and a real Windows junction. Image tests cover dimensions, hashes, limits, transparency and overwrite. Local checks pass **123 Node and 42 Python tests**, typecheck and build; npm audit reports zero advisories. CI runs all Python tools tests alongside typecheck, Node tests and build. Native results are local validation, not GitHub Actions coverage.

Enabling the previously omitted native-image tests on a clean Linux runner exposed an undeclared existing NumPy import. The visual requirements now include NumPy; the initial failed CI run is retained rather than described as a test failure in vehicle behavior.

## Reuse and remaining limits

Start from [workflows.md](workflows.md), review the [adapter contract](workflow-adapters.md), and use [recovery](workflow-recovery.md) for errors and takeover. [Damage case recipes](../examples/workflows/damage-cases.example.json) show stimulus/reset/functional contracts; the [inert scaffold](../examples/workflows/adapter_scaffold.py) emits NOT_TESTED until an addon-owned native implementation exists.

The camera/audio/compile/package tools remain the established implementations. Mobility, crew/input, audio integration, geometry/material and release templates consolidate their observed gates; they are not newly qualified native adapters for every vehicle. Multi-renderer operation, MP/JIP/dedicated behavior, ordinary player input and full physical usability remain explicit limits. No publisher agreement or submission is automated. Reusable adapters should grow from observed next tasks rather than a speculative universal engine framework.
