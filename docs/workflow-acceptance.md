# Audit acceptance and remaining scope

This matrix separates implemented tools, representative evidence and remaining
qualification. A workflow can be useful while a measured scenario fails. None
of these results qualifies the frozen Gepard release or changes publication
ownership. Source fingerprints and benchmarks are in the
[sanitized validation receipt](audits/workflow-validation-2026-10.json); exact
private commands, jobs and raw artifacts remain in the local audit handoff.

| Workflow | Implemented and exercised | Remaining qualification / disposition |
|---|---|---|

Actual catalog missing-base and missing-class fixtures refuse before launch. The stopping boundary is evidence-driven: observed expensive setup omissions,
misleading health/input/kinematic acceptance, weak result reporting, cancellation,
image limits and mismatched visual comparisons now have concrete checks or tools
and representative validation. Further generic abstraction would not qualify a
new engine behavior. Slope/traction courses, concurrency, multiplayer, full human
input, new audio work and publisher decisions need separate native fixtures or
user availability; they remain explicit rather than speculative infrastructure.

For the next task: select a template in [workflows.md](workflows.md), bind a
qualified addon adapter and frozen fixture, add the request's required assertions,
plan, run into fresh output, then read the index and raw evidence. Use
[recovery](workflow-recovery.md) for an infrastructure/ownership boundary. A
known scenario FAIL can still be the correct reusable regression result.
