# Raven AI Commander field notes

This record separates the author's feature descriptions from behavior observed on this machine. The question is whether a player can easily direct an AI supply delivery and whether the AI recovers when a run fails.

## Published claims, not yet gameplay-verified

The [Workshop listing](https://reforger.armaplatform.com/workshop/6A3A112604EF7286-RavenAICommander) and [changelog](https://reforger.armaplatform.com/workshop/6A3A112604EF7286-RavenAICommander/changelog) describe an automatic Conflict logistics system: faction/HQ/depot and truck discovery, logistics vehicle and crew creation, supply-run task claiming, a physical convoy with a virtual-cargo fallback, and resource transfer after a successful return. They also describe a retry delay for convoy **start failures** and waypoint fixes for dedicated servers. They do not document a player menu, radio command, source/destination order, or recovery from a truck stuck mid-route or a dead driver. Absence from the listing is not proof that an in-game control does not exist.

Raven is described for Conflict-based PvE, including its [companion Raven Conflict PvE scenario](https://reforger.armaplatform.com/workshop/6A3A581735B02A50-RavenConflictPvE). A Game Master world alone is not an adequate logistics test.

Read-only inspection of the installed packed scripts (decompressed in memory; no files unpacked or redistributed) found no player menu, radio command, or input handler for delivery orders. Its faction context queues an automatic `SUPPLY_RUN` when HQ stock is below 500 and no run is open, aiming from the nearest depot back to HQ for 750 supplies. The convoy director checks source, vehicle, HQ, and crew before claiming; Arland startup logged those four as available. The first `SUPPLY_RUN CLAIMED` appeared after the player placed two Game Master transport trucks near US HQ, but Raven's code uses its earlier bound vehicle rather than scanning those trucks. The sequence is temporal correlation; the cause of the delay is unresolved. Keep the claim/start separate from proof of an actual delivery.

The packed runtime registers repeating commander, transport, economy, construction, and performance callbacks before announcing startup, at roughly 2 to 5 second intervals. First transport initialization produced `FACTION LOGISTICS READY` about 2.5 seconds after runtime start. We initially inferred a low-stock run would be logged within seconds; the actual claim came about 15 minutes later. The scheduling alone did not explain the delay. The convoy's logged state `1` means boarding; state `2` means the crew switched to an outbound waypoint, not that the vehicle reached its source. A later state would be needed for loading, return, unloading, or completion. [Enfusion's CallLater API](https://community.bistudio.com/wikidata/external-data/arma-reforger/EnfusionScriptAPIPublic/interfaceScriptCallQueue.html) documents the repeat mechanism used by the addon.

The Game Master interaction log is `.cache/client/runs/2026-09-24T18-16-39-229Z-28924/logs/console.log`; the successful player-hosted Conflict log is `.cache/client/runs/2026-09-24T18-46-40-134Z-24108/logs/console.log`. Exact UI steps and launch commands are in [the operations playbook](operations-playbook.md). The installed Workshop package reports version 1.0.6, while some runtime log lines still use an older-looking Raven prefix; search for event text such as `AUTO RUNTIME STARTED`, `FACTION LOGISTICS READY`, and `SUPPLY_RUN` instead of relying on the prefix.

## Current access blocker

Automatic joining of a hidden local Conflict server timed out during authentication in Raven and vanilla controls. Changing only the advertised server address to `local` did not resolve it. The separate player-hosted Conflict path worked once the user physically focused the game window and cleared **Press Enter to continue**. The desktop controller has not independently dismissed that gate yet. The in-game Workshop registered Raven for Host Mods, and the private player-hosted Conflict run reached Deployment Setup with Raven initialized. This is a working local handoff path; it does not establish that Raven completes supply deliveries.

## Next decisive gameplay test

Enter a Raven-enabled Conflict scenario, then record: the player-facing action path and setup time; whether source, destination, and amount can be chosen; actual source and destination resource counts; truck departure and arrival; and what happens after a stuck vehicle or lost crew. Raven's notes give no player delivery command; observe normal Conflict supply sources and destinations, and look for `SUPPLY_RUN CLAIMED` or `SUPPLY_RUN BLOCKED` in the current server log. A claim or moving truck alone does not prove a transfer; compare resource counts after arrival. If no task appears, record elapsed time, ownership, stock, and logs. Until that run, ease of player-directed delivery and recovery remains unverified.
